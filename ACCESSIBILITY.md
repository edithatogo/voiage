# Accessibility

Voiage aims to make its documentation, analysis tools, and contribution process
usable by people with disabilities. We welcome reports about barriers in the
documentation, package interfaces, and GitHub workflows.

## Using voiage

- Find installation options and runtime requirements in the
  [getting started guide](https://edithatogo.github.io/voiage/getting-started/).
- Run analyses through the language APIs or the command line. The
  [CLI reference](https://edithatogo.github.io/voiage/cli-reference/) describes
  the available commands and output formats.
- The experimental qualitative assessment command offers plain-text output
  with headings and status labels. The
  [plotting guide](https://edithatogo.github.io/voiage/user-guide/plotting/)
  describes optional plots based on the numerical results.

## Known limitations

Some plots use colour and layout to convey results. Screen-reader and keyboard
testing is limited across the documentation site, notebooks, and rendered plots.

## Report a barrier

Use the [accessibility issue template](https://github.com/edithatogo/voiage/issues/new?template=accessibility.md).
Tell us which page or command you were using, what you were trying to do, and
what made it difficult. If you know what would help, include that too.
Browser, operating system, and assistive technology details are optional.

GitHub issues are public. Share only details you are comfortable making public.
The maintainer triages reports through the [project support process](SUPPORT.md).
