# Blocker-Resolution Plan

## Options

1. **Evidence-led programme coordination (recommended):** keep the root track
   responsible for synchronized plans, issue/Project mappings, maturity and
   language dispositions, while each child track owns implementation and
   acceptance evidence.
2. **Umbrella promotion:** mark the programme complete when most child tracks
   are locally green. This is fast but collapses distinct scientific,
   installed-parity, registry, publication, and hosted gates and is unsafe.
3. **Freeze programme work:** make no further changes until every external gate
   is satisfied. This avoids drift but prevents useful repository-owned
   reconciliation and evidence maintenance.

## Recommendation

Use option 1. The root track should remain in progress until every workstream
has a reconciled plan and evidence, while external gates remain explicit and
fail-closed. Local validation may establish repository integrity but cannot
substitute for scientific review, clean installed binding evidence, registry
acceptance, release approval, or issue closure.

## Contingencies and exit criteria

- If a child track is externally blocked, record the exact gate and retain its
  honest maturity state; do not promote the root programme.
- If a binding or frontier capability lacks installed evidence, classify it as
  contract-only, adapter, unsupported, or upstream-blocked.
- Archive the root track only after all ten workstream plans and evidence are
  reconciled, final local and hosted checks pass, and remaining external gates
  are separately recorded rather than silently treated as complete.
