---
title: Versioned C ABI
description: The v1 portable C ABI contract used by retained bindings.
---

The versioned C ABI is the narrow native boundary for retained bindings. The
header is authoritative for declarations; the symbol and layout manifests are
the release allowlists.

## Version negotiation and capabilities

- ABI major: `1`; ABI minor: `7`
- Capability-struct version: `1`
- Capability bits include version negotiation, capability query, scalar EVPI,
  the typed EVPI result envelope, and the registry-generated capability
  document, typed expected loss with caller-owned arrays, and ENBS.
  Deterministic dominance, frontier, and ICER results are also available.
  CEAF exposes threshold-aligned acceptability and assurance outputs.
  Structural EVPI and EVPPI expose model-form uncertainty and assurance.
- `VoiageHandleV1` is an opaque process-local token; zero is null and tokens
  are never exposed addresses.

## Exported v1 symbols

```text
voiage_v1_abi_version
voiage_v1_capabilities
voiage_v1_capabilities_json
voiage_v1_ceaf_result
voiage_v1_evpi
voiage_v1_enbs
voiage_v1_dominance_result
voiage_v1_evpi_result
voiage_v1_expected_loss_result
voiage_v1_evpi_i32
voiage_v1_evpi_i32_r
voiage_v1_error_message
voiage_v1_handle_create
voiage_v1_handle_free
voiage_v1_structural_evpi_result
voiage_v1_structural_evppi_result
```

The EVPI functions delegate to the Rust numerical kernel. The `i32` and `i32_r`
forms exist for runtimes whose foreign-function conventions use signed 32-bit
dimensions; they do not define a separate numerical policy.
`voiage_v1_evpi_result` preserves the scalar value and adds sample and strategy
counts plus explicit variance and Monte Carlo standard-error availability.

`voiage_v1_capabilities_json` returns canonical UTF-8 JSON generated from the
stable-core status registry. A null, zero-capacity buffer queries its required
size, including the trailing NUL. The caller owns all output storage, and an
undersized buffer is left untouched.

`voiage_v1_expected_loss_result` writes expected net benefit and expected
opportunity loss into two caller-owned arrays, plus a fixed-width summary with
the optimum strategy, dimensions, minimum expected loss, variance, and Monte
Carlo error. Capacity, nullness, and alignment are validated before any output
is written.

`voiage_v1_enbs` delegates to the Rust ENBS kernel and returns raw
`EVSI - research cost`; negative net value is valid and is not clipped.

`voiage_v1_dominance_result` writes one classification per strategy, ordered
frontier indices, and transition-aligned incremental costs, effects, and ICERs.
Classification codes are `0` frontier, `1` strongly dominated, and `2`
extended dominated. Both worst-case capacities are validated before any
output is written.

`voiage_v1_ceaf_result` consumes row-major
`[sample][strategy][threshold]` net benefit and writes threshold-aligned
optimum indices, acceptability probabilities and intervals, selected expected
net benefit, assurance availability, variance, and Monte Carlo error.

`voiage_v1_structural_evpi_result` and
`voiage_v1_structural_evppi_result` consume row-major
`[structure][sample][strategy]` net benefit and explicit model probabilities.
Structural EVPPI additionally consumes caller-owned selected-structure
indices. Both return dimensions, the structural value, assurance availability,
informed-value variance, and Monte Carlo error without writing on failure.

## Status and error transport

Status values are fixed-width: `OK`, `INVALID_ARGUMENT`, `DIMENSION_MISMATCH`,
`BACKEND_UNAVAILABLE`, `NUMERICAL_FAILURE`, `SERIALIZATION_FAILURE`,
`BUFFER_TOO_SMALL`, `PANIC`, and `INTERNAL_ERROR`.

`voiage_v1_error_message` uses caller-owned storage. A null buffer with zero
capacity queries the required size, which includes the trailing NUL. No partial
message is written when the buffer is too small.

## Fixed-width layouts

| Type | Size | Alignment | Stable fields |
| --- | ---: | ---: | --- |
| `VoiageAbiVersionV1` | 12 | 4 | `struct_size@0`, `abi_major@4`, `abi_minor@8` |
| `VoiageAbiCapabilitiesV1` | 16 | 8 | `struct_size@0`, `struct_version@4`, `capability_bits@8` |
| `VoiageEvpiResultV1` | 56 | 8 | versioned value, dimensions, assurance availability, variance, and Monte Carlo error |
| `VoiageExpectedLossResultV1` | 64 | 8 | optimum strategy, dimensions, minimum loss, assurance availability, variance, and Monte Carlo error |
| `VoiageDominanceResultV1` | 48 | 8 | strategy, frontier, dominance, and transition counts |
| `VoiageCeafResultV1` | 32 | 8 | sample, strategy, and threshold counts |
| `VoiageStructuralVoiResultV1` | 64 | 8 | value, dimensions, assurance availability, variance, and Monte Carlo error |
| `VoiageHandleV1` | 8 | 8 | opaque token |
| `voiage_v1_status` | 4 | 4 | fixed-width status |

The canonical manifests are [`symbols.txt`](https://github.com/edithatogo/voiage/blob/main/specs/abi/v1/symbols.txt)
and [`layouts.txt`](https://github.com/edithatogo/voiage/blob/main/specs/abi/v1/layouts.txt).
Bindings must run the ABI lifecycle, error, and shared numerical conformance
tests before publication.
